# Minecraft Java 26.2 NeoForge fallback

## Use this when Fabric is not suitable

**Project language:** English 
**Target:** Minecraft Java Edition 26.2, NeoForge, Java/Bedrock cross-play 
**Example platform:** Windows 10/11

> **Important terminology:** for a modern 26.2 server, use **NeoForge**, not the old/classic Forge workflow. Forge and NeoForge are separate loaders and their mods are not interchangeable. A Forge `.jar` is not automatically a NeoForge `.jar`.

---

## 1. When should you choose NeoForge?

Choose NeoForge if:

- a required mod has no Fabric build;
- your chosen modpack is published for NeoForge;
- your technical/gameplay mods are more complete or better maintained on NeoForge;
- Fabric testing has shown a real compatibility problem.

Choose Fabric instead if all required mods already work there. Changing loaders does not automatically improve performance or plugin compatibility.

### Critical plugin warning

NeoForge is a **mod loader**, not a Bukkit/Spigot/Paper plugin server. Installing NeoForge does not create a `plugins/` folder that can run arbitrary Bukkit plugins.

You have three possible architectures:

| Priority | Recommended architecture |
|---|---|
| Fabric mods and technical gameplay | Fabric + native Fabric mods + Geyser-Fabric |
| NeoForge-only mods or modpack | NeoForge + native NeoForge mods + Geyser-NeoForge |
| Many mature Bukkit plugins | Paper/Spigot + Geyser, without NeoForge mods |
| Both a specific modpack and specific Bukkit plugins | A hybrid project only if it publishes an exact 26.2 build; test it on a disposable server first |

Do not install a random old Mohist, Magma or Arclight build because its name says Forge. A hybrid server can break mods, plugins, performance and world data. Never use a hybrid build for production until the exact Minecraft version, loader version, mod list and plugin list have been tested together.

## 2. Final NeoForge layout

```text
C:\MinecraftServer\
├── neoforge-26.2-...-installer.jar (installer; can be kept or removed)
├── run.bat (generated by NeoForge)
├── user_jvm_args.txt
├── eula.txt
├── server.properties
├── mods\
│ ├── Geyser-NeoForge-<compatible>.jar
│ ├── floodgate-neoforge-<compatible>.jar
│ ├── lithium-or-equivalent-<compatible>.jar
│ └── carpet-or-technical-mod-<compatible>.jar
├── config\
│ ├── Geyser-NeoForge\config.yml
│ └── floodgate\key.pem (private; never publish)
└── world\
```

The exact filenames change. Do not rename a mod file unless the project specifically tells you to.

## 3. Install Java

When using the Jarock repository, Java discovery is handled by `scripts/java-runtime.ps1`. The selected Java executable is stored locally in `server/java-path.txt`. The repository now offers NeoForge as a first-run fallback. `parameter-manager.bat` can select NeoForge, and `start-server.bat` runs the official NeoForge installer automatically. NeoForge remains a separate loader and must use its own mods; the official generated `run.bat` is the runtime entry point because modern NeoForge does not provide a portable single loader jar to rename safely.

Install a current 64-bit Java runtime suitable for Minecraft 26.2. For the 26.x line, Java 25 is the expected starting point, but follow the requirement shown by the current NeoForge installer and official Minecraft tooling if it differs.

Open Command Prompt and run:

```bat
java -version
```

Confirm that:

- Java is available as a command;
- the major version is the one required by the 26.2 tooling;
- the runtime is 64-bit.

If the command is not found, install Java from a trustworthy distributor or ask your hosting provider to select the correct Java runtime. If several Java versions are installed, make sure the server panel or `PATH` uses the intended one.

## 4. Install the NeoForge server

Jarock performs these steps automatically after the user selects NeoForge. For manual recovery or troubleshooting:

1. Create a clean folder such as `C:\MinecraftServer`.
2. Open the official NeoForge project/download page: <https://neoforged.net/>.
3. Select the NeoForge release for Minecraft **26.2**.
4. Download the official installer `.jar`.
5. Put the installer in `C:\MinecraftServer`.
6. Open Command Prompt and run:

```bat
cd /d C:\MinecraftServer
java -jar neoforge-<version>-installer.jar --installServer
```

Replace `<version>` with the real installer filename. Do not type the angle brackets.

The installer creates files including a Windows launcher such as `run.bat`, libraries and `user_jvm_args.txt`.

### Configure memory

Open `user_jvm_args.txt` and follow the comments already supplied by NeoForge. Start conservatively:

- 4 GB for a small test server;
- 6 GB for a larger modded server if the host has enough total RAM.

Do not give all system memory to Minecraft. Leave memory for Windows, Java, backups and other services.

---

## 5. First start and EULA

1. Double-click `run.bat`.
2. The first run normally stops and creates `eula.txt`.
3. Read <https://www.minecraft.net/eula>.
4. If you agree, change:

```text
eula=false
```

to:

```text
eula=true
```

5. Save the file.
6. Start `run.bat` again.

When the server is ready, stop it safely from the console with:

```text
stop
```

Do not forcibly close the window while the world is saving.

## 6. Install NeoForge mods

After the first successful start, NeoForge creates a `mods` directory.

Only download mods that explicitly list:

- Minecraft 26.2;
- NeoForge, not just Forge or Fabric;
- dedicated-server support, when applicable;
- all required dependencies.

Recommended sources are the project's official download page, Modrinth and CurseForge. Do not use random re-upload sites. Put the `.jar` files directly into:

```text
C:\MinecraftServer\mods
```

Do not unzip them.

### Performance and technical mods

Use the exact NeoForge 26.2 versions available for your selected stack. Possible roles include:

- game-logic optimization;
- memory optimization;
- networking optimization;
- server performance controls;
- technical/redstone tools.

The Fabric versions of Lithium, FerriteCore, Krypton or Carpet cannot simply be copied into NeoForge. Each project must provide a NeoForge build. If it does not, find a NeoForge alternative or omit it.

Install one mod at a time:

1. Stop the server.
2. Add one compatible `.jar`.
3. Start `run.bat`.
4. Check `logs/latest.log`.
5. Join with Java.
6. Test Bedrock if Geyser is installed.
7. Keep a backup before the next change.

Client-only mods such as Sodium, Litematica, MiniHUD or Tweakeroo do not belong in the dedicated server's `mods` folder unless the mod author explicitly says otherwise.

## 7. Install Geyser-NeoForge

Geyser's official modded-server guide lists **Geyser-NeoForge** for NeoForge and Minecraft 26.2:

- Geyser downloads: <https://geysermc.org/download>
- Modded server setup: <https://geysermc.org/wiki/geyser/setup/self/modded-servers/>
- Supported versions: <https://geysermc.org/wiki/geyser/supported-versions/>

Download the NeoForge build that explicitly supports Minecraft 26.2 and put it in:

```text
C:\MinecraftServer\mods
```

Restart the server once. Geyser creates:

```text
C:\MinecraftServer\config\Geyser-NeoForge\config.yml
```

Open that file and check the Bedrock listener:

```yaml
bedrock:
 address: 0.0.0.0
 port: 19132
 clone-remote-port: false
```

Preserve the existing YAML indentation. If your host assigns a different UDP port, use that port instead of `19132`.

Geyser-NeoForge is intended for a current 26.2 server. If you deliberately choose an older Minecraft version, use the Geyser architecture documented for that older version rather than forcing the 26.2 mod into it.

## 8. Install Floodgate-NeoForge

Floodgate is optional. Without it, Bedrock players need the authentication arrangement required by Geyser. With it, authenticated Bedrock players can join without owning Java Edition.

From the official Geyser/Floodgate downloads, select the current **Floodgate-NeoForge** build for the target server and place its `.jar` in:

```text
C:\MinecraftServer\mods
```

The project may present multiple platform files under one download page. Do not accidentally install `floodgate-fabric` on NeoForge.

In Geyser's config, set:

```yaml
auth-type: floodgate
```

Restart the server and read the console for errors.

### Protect the Floodgate key

Floodgate creates a private key file, commonly named `key.pem`. It is a credential. Never:

- upload it to GitHub;
- send it to a stranger;
- put it inside a public backup;
- reuse a key copied from an unrelated server.

If you later add a proxy, follow the official Floodgate proxy instructions. Do not copy keys between servers unless the official setup specifically requires it.

## 9. Network settings

The default connections are:

| Edition | Default port | Protocol |
|---|---:|---|
| Java | `25565` | TCP |
| Bedrock through Geyser | `19132` | UDP |

A hosting provider may assign other ports. Use the provider's values in `server.properties`, Geyser's config and the instructions given to players.

For a home server:

1. allow the Java TCP port through Windows Firewall;
2. allow the Geyser UDP port through Windows Firewall;
3. forward the Java TCP port in the router;
4. forward the Geyser UDP port in the router;
5. do not share the Geyser UDP port with voice chat, query or another UDP service.

For a tunnel, use a solution that supports UDP, such as the `playit.gg` approach documented by Geyser. A TCP-only tunnel does not carry Bedrock traffic.

Test Geyser when available:

```text
geyser connectiontest your.public.address 19132
```

## 10. Configure the server safely

Stop the server before editing `server.properties`. Start with:

```properties
online-mode=true
white-list=false
enforce-whitelist=false
server-port=25565
view-distance=8
simulation-distance=6
```

Keep `online-mode=true`. Floodgate is not a reason to make the entire server offline-mode. The whitelist is disabled by default so anyone can join for testing; before public access, set `white-list=true` and `enforce-whitelist=true` and add every trusted player.

Add a Java player:

```text
whitelist add JavaPlayerName
```

For Bedrock, use the exact Floodgate username shown by the console. Floodgate may add a prefix. Its command and username behavior can change, so consult the current Floodgate documentation instead of guessing.

## 11. Bedrock limitations with NeoForge mods

Geyser translates the Java/Bedrock protocol; it does not install NeoForge mods on a Bedrock device. Bedrock players will not automatically receive:

- custom Java client rendering;
- Java-only HUDs and minimaps;
- arbitrary custom blocks, items or entities;
- a mod that requires every client to install the mod;
- every custom dimension or resource system.

A server-side mod that preserves vanilla blocks, items and entities has the best chance of working. Test the real gameplay, farms and redstone mechanisms used by your community.

If the modpack requires every Java player to install a large client modpack, it is usually not a good candidate for transparent Bedrock cross-play. Do not promise compatibility until a Bedrock test has passed.

## 12. Backups and updates

Before changing NeoForge, Geyser, Floodgate or any mod:

1. run `stop`;
2. back up `world`, `world_nether`, `world_the_end`, `config`, `mods`, `server.properties` and `whitelist.json`;
3. date the backup;
4. update one component;
5. start the server;
6. test Java and Bedrock;
7. keep the backup until the new version is proven stable.

Never publish the Floodgate private key or its configuration directory. The exact path can vary by build; commonly it is under the Floodgate configuration directory, such as `config/floodgate/key.pem`:

```text
world/
world_nether/
world_the_end/
config/floodgate/
logs/
```

Always back up before upgrading NeoForge or mods. Do not downgrade a world after opening it in a newer Minecraft release unless the official documentation explicitly supports it.

## 13. Troubleshooting

### NeoForge refuses a mod

The mod is probably for Fabric, classic Forge, another Minecraft version, or a different NeoForge version. Remove it and download the correct build. Do not ignore loader errors.

### The server crashes at startup

Read the first meaningful error in `logs/latest.log` and the newest file in `crash-reports/`. Common causes are missing dependencies, duplicate files, client-only mods and incompatible versions.

### Java works but Bedrock does not

Check that:

- Geyser-NeoForge is loaded;
- Floodgate-NeoForge is loaded if Floodgate authentication is enabled;
- the Geyser UDP port is correct;
- UDP is allowed by the firewall, router and host;
- no other service uses that UDP port;
- the Bedrock client is supported by the current Geyser release.

### Bedrock joins but is kicked

Check `auth-type: floodgate`, Floodgate's version, whitelist formatting and the console. Do not set `online-mode=false` as a workaround.

### A plugin does not load

That is expected on a normal NeoForge server: NeoForge loads NeoForge mods, not arbitrary Bukkit plugins. Either find a native NeoForge mod, change to a plugin-first Paper architecture, or test an exact 26.2 hybrid server in a separate world.

### The server is laggy

Measure before adding more mods. Check CPU, entity counts, chunk generation, view distance and simulation distance. Use only current NeoForge 26.2 optimization mods and add them individually.
