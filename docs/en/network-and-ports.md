# Network, Firewall, and Router Configuration for Jarock

> **Important:** Jarock never opens router ports, changes firewall rules, or configures port forwarding automatically. This guide explains how to do those tasks manually, safely, and in the correct order.

---

## 1. Before you start

**Java note:** If you install the Eclipse Temurin JDK, enable the **"Set JAVA_HOME variable"** checkbox during setup (click the red X and select "Will be installed on local hard drive"). Without `JAVA_HOME`, Jarock may not find Java.

Complete the items in `TODO.md` before exposing the server publicly:

- [ ] Java and Bedrock joining works on `localhost`.
- [ ] `online-mode=true` is enabled and the whitelist is enabled (`white-list=true`, `enforce-whitelist=true`) before public access; it is disabled by default.
- [ ] Floodgate `key.pem` is kept private and never published or committed.
- [ ] A working backup exists and you have verified you can restore it.

## 2. Which ports does Jarock use?

| Edition | Default port | Protocol | Where it is configured |
|-----------|-------------|----------|------------------------------------------------------|
| Java | 25565 | TCP | `server/server.properties` → `server-port` |
| Bedrock | 19132 | UDP | Geyser config (generated by the loader) |

- Both ports must be distinct. Never share the UDP port with voice chat, query, or another UDP service.
- If a hosting panel assigns different ports, use the assigned values in both the configuration files and the connection instructions.

## 3. Assign a static LAN IP to the server computer

Your router forwards ports to a specific local IP. If that IP changes after a reboot, the forwarding breaks.

**Windows 10 / 11:**

1. Open **Settings → Network & Internet → Ethernet** (or Wi-Fi).
2. Click your active connection, then **Hardware properties**.
3. Write down:
 - **IPv4 address** (e.g. `192.168.1.42`)
 - **Subnet mask** (usually `255.255.255.0`)
 - **Default gateway** (e.g. `192.168.1.1`)
 - **DNS servers** (e.g. `192.168.1.1` and `1.1.1.1`)
4. Go back to **Network & Internet → Advanced network settings → More network adapter options**.
5. Right-click your adapter → **Properties** → **Internet Protocol Version 4 (TCP/IPv4)** → **Properties**.
6. Select **Use the following IP address** and enter the values you wrote down.
7. Click **OK** and close.

**Alternative:** reserve the IP in your router's DHCP settings instead. That is safer if you share the network, because Windows keeps using automatic IP assignment.

## 4. Allow the ports in Windows Defender Firewall

If Windows does not ask automatically, create the rules manually.

### Java (TCP 25565)

1. Open **Windows Defender Firewall with Advanced Security** (`wf.msc`).
2. Click **Inbound Rules → New Rule**.
3. Select **Port → TCP → Specific local ports: `25565`**.
4. Select **Allow the connection**.
5. Check **Domain**, **Private**, and **Public** (or only **Private** if the PC is only used at home).
6. Name it: `Jarock Java (TCP 25565)`.
7. Click **Finish**.

### Geyser / Bedrock (UDP 19132)

Repeat the steps above with:

- **Protocol:** UDP
- **Port:** `19132`
- **Name:** `Jarock Bedrock (UDP 19132)`

> If your host or tunnel assigns different ports, use those values instead.

## 5. Configure router port forwarding

Every router has a different interface. The general steps are the same.

### What you need

- The **static LAN IP** of the server computer (from step 3).
- The **Java TCP port** (default `25565`).
- The **Geyser UDP port** (default `19132`).

### General steps

1. Log in to your router. The address is usually the **default gateway** (e.g. `192.168.1.1`).
2. Find the section called **Port Forwarding**, **Virtual Server**, or **NAT**.
3. Create a new rule:

 | Setting | Java rule | Bedrock rule |
 |----------------|-------------------|--------------------|
 | Service name | `Jarock Java` | `Jarock Bedrock` |
 | Protocol | TCP | UDP |
 | External port | 25565 | 19132 |
 | Internal port | 25565 | 19132 |
 | Internal IP | Your static LAN IP| Your static LAN IP |

4. Save and apply.

### Find your public IP

Open a browser and go to:

- `https://whatismyipaddress.com`
- or `https://ipinfo.io`

The IPv4 address shown is what other players need. If your ISP uses CGNAT (Carrier-Grade NAT), you will not receive a public IPv4 address and a VPN tunnel is required.

### Test from outside your network

Use a mobile phone on cellular data, or ask a friend:

- Java: `<public-ip>:25565`
- Bedrock: `<public-ip>` port `19132`

If it does not connect:

1. Double-check the LAN IP in the router rule matches the server PC.
2. Confirm Windows Firewall allows both ports.
3. Verify the ISP does not block the ports (call them if unsure).
4. Check that no other application is using those ports.

## 6. Using a tunnel instead of port forwarding

If port forwarding is not possible (CGNAT, ISP blocks, no router access), a tunnel is the alternative.

| Tunnel | TCP (Java) | UDP (Bedrock) | Notes |
|------------------|------------|---------------|------------------------------------------------------|
| playit.gg | Yes | Yes | Specifically documented by Geyser. |
| Ngrok (basic) | Yes | No | TCP-only; not suitable for Bedrock. |

- A TCP-only tunnel **cannot** carry Bedrock UDP traffic. Both Java and Bedrock players need their respective transport.
- The tunnel provides an address and port; use those values instead of the public IP.
- Test Java first, then Bedrock.

## 7. Security checklist before going public

- [ ] `online-mode=true` — cracked-mode is unsafe on a public server without a trusted authentication proxy.
- [ ] `white-list=true` — only approved players should join (disabled by default; enable it before going public).
- [ ] `enable-query=false` — unless you know why you need it.
- [ ] `enable-rcon=false` — unless you secure it with a strong password and firewall rules.
- [ ] Floodgate `key.pem` is not shared, published, or committed.
- [ ] Geyser config does not expose debug endpoints publicly.
- [ ] Backups run automatically and you have tested a restore.
- [ ] Java and Bedrock ports are distinct and only the required ports are open.

## 8. Common problems

| Problem | Likely cause | Fix |
|--------------------------------------------|------------------------------------------------|------------------------------------------------------------------|
| "Can't connect to server" | Port not forwarded or firewall blocking | Check steps 4 and 5. |
| Java works, Bedrock does not | UDP port not forwarded or TCP-only tunnel | Forward UDP separately or switch to a UDP-capable tunnel. |
| Works on LAN but not from the internet | Router port forwarding missing or ISP blocks | Verify the router rule and ask the ISP. |
| Works yesterday, broken today | LAN IP changed | Set a static IP or DHCP reservation (step 3). |
| Server list shows "Old" or "Can't connect" | Firewall, wrong port, or server not running | Check the server console is live and ports are open. |
